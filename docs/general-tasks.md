# 通用消息任务 v1.1

任务场景：普通消息通知、回访问卷。历史任务兼容为回访问卷，历史未填版本不强制补录；新问卷需选择版本。子业务类型、Android 通道与任务场景独立。

普通通知固定创建时的 UID 人群，按批次 + UID + 载体生成消息，无产品、业务消息、完成结果或快照。问卷保留用户 + 任务 + 产品唯一业务消息及原始快照，补发不新建业务消息。列表分场景展示；业务消息两个菜单仅包含问卷记录。

Push 下发、点击及弹窗下发、曝光、点击按载体 ID 去重；Push UV 按 UID 在所选任务或批次内去重，任务 UV 不累加批次 UV。Push 点击率 = 已点击载体数 / 下发载体数；弹窗点击率 = 已点击载体数 / 下发载体数；曝光点击率 = 已点击载体数 / 曝光载体数。零分母显示 —。

普通补发范围为原始个人用户、任务内未点击任意载体用户、弹窗未曝光用户。没有失败回执，不提供失败筛选。问卷仅补发未提交个人用户。终止和到期任务不可补发，任务结束由生效时间决定，与业务完成率无关。前端开启时每 30 秒推进本地任务状态；关闭页面后没有调度。

## 正式后台落地边界

当前交付为本地交互原型；未连接真实用户库、推送服务、事件采集和数据库。

建议表：task（scene、配置、起止时间、生命周期），task_target（task_id + uid 唯一、创建时的人群和筛选依据），batch、batch_target（batch_id + uid 唯一），carrier_message（batch_id + uid + channel 唯一），carrier_event（event_id 幂等、carrier_id、event_type、事件时间），biz_msg（task_id + uid + product_id 唯一）、baseline_snapshot、answer_snapshot、carrier_biz_relation（多对多）。问卷相关表仅由问卷场景生成。

创建与首次批次通过事务及 outbox 提交；调度器按时间触发，下发前重新校验注销、推送开关、黑名单和频控并记录排除原因；失败回执接入后再增加失败重试。重试复用幂等键，补发使用新批次。答卷唯一约束防并发重复提交；答卷写入与业务结果回写同事务。事件消费按事件 ID 幂等，指标按载体/用户聚合，迟到事件回补。任务和批次列表/导出使用同一统计服务，所有创建、终止、补发及结果修改留审计日志。


## 2026-10-16 已确认规则修订

以 PRD 第13节确认规则为准：下发条数=计划发送数；结束时间同时控制发送和作答。弹窗按任务＋UID跨设备频控，从有效曝光起算24/72/168小时，补发不重置，未曝光不扣次数，周期一次指整个任务。问卷所有产品业务消息完成（正常、异常、人工录入均计）后停止新弹窗。私募人群按创建快照时持仓圈定，后续清仓排除触达；高龄≥65岁；导入UID直接指定且不要求持仓，非法/不存在/不符合资格须返回原因。问卷按全部符合条件持仓产品生成业务消息；模板与答卷PDF分开保存，复核不覆盖原始文件。本期仅Push/弹窗，权限、容量和服务要求不考虑。真实持仓、跨设备曝光和PDF归档仍需接入后台。
