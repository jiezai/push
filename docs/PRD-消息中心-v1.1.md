## 1. 背景与目标

原有能力围绕投资者适当性回访问卷构建，包含目标人筛选、业务消息、基线快照、批次触达、问卷答卷、回访复核及完成统计。普通运营通知只需要 Push／App 弹窗及触达效果，不应被迫生成产品业务消息或统计业务完成率。

本次将任务分为“普通消息通知”和“回访问卷”，共用任务、目标用户、批次、载体配置与运营统计；问卷场景单独保留业务消息与快照。

目标：

- 支持运营通知与问卷触达共用后台，减少重复建设。
- 区分任务生命周期、业务完成状态与载体事件，避免统计混淆。
- 支持原始人群内补发，历史基线、答卷及操作记录可追溯。
- 统一任务、批次、列表与导出的统计口径。

本期不新增邮件、短信、自定义审批流或可视化问卷设计器。普通通知的站内信渠道未实现；业务消息不可等同于所有通知的站内信。

## 2. 角色与信息架构

### 2.1 角色

| 角色 | 主要能力 | 实现状态 |
| --- | --- | --- |
| 运营管理员 | 创建、查询、终止、补发任务，修改业务结果，导出 | 原型已模拟；正式权限待接入 |
| 查询人员 | 查询任务、载体、业务明细及授权导出 | 正式角色建议；原型无独立登录 |
| 个人客户 | 接收 Push／弹窗，打开落地页，提交问卷 | 原型提供问卷预览；真实 App 待接入 |
| 机构／产品客户 | 由运营线下跟进并录入业务结果 | 问卷场景支持，无 Push／弹窗 |

### 2.2 左侧菜单

按以下顺序展示，当前均为同级菜单：

1. 任务管理。
2. 业务消息管理。
3. 业务消息明细。
4. 推送/弹窗明细。

业务消息管理可操作结果；业务消息明细只读，保留筛选、重置和导出，不提供编辑、快照操作或批量结果修改。两个业务菜单仅承载回访问卷业务记录。推送/弹窗明细同时承载两类任务。

### 2.3 核心对象

| 对象 | 粒度 | 说明 |
| --- | --- | --- |
| 任务 | task_id | 一次运营活动或回访计划 |
| 目标用户 | task_id + uid | 创建时固定的用户集合 |
| 批次 | batch_id | 首次下发或一次补发 |
| 批次目标用户 | batch_id + uid | 本次入选用户 |
| 载体消息 | batch_id + uid + channel | 一个用户在一个批次的一种载体实例 |
| 业务消息 | task_id + uid + product_id | 问卷场景某用户某产品的完成记录 |
| 基线快照 | snapshot_id | 创建时的客户、持仓、风险及问卷版本 |
| 答卷快照 | 业务消息对应唯一答卷 | 保留原始提交内容，不随复核改变 |

同一用户多产品可对应多条业务消息，但每批次每种载体仅一条；通过关联关系连接业务消息，避免按产品重复推送。

## 3. 任务管理

### 3.1 列表

顶部展示全部任务、执行中、待执行、已完成数量，点击应用相应状态筛选。列表页签：全部任务、普通消息通知、回访问卷。

筛选：任务名称或 ID 模糊查询、任务状态、创建日期范围；组合条件按 AND 生效，支持查询、重置。状态选项固定顺序：待执行、执行中、已完成、已终止。

| 列表 | 展示字段 |
| --- | --- |
| 通用字段 | 任务名称、任务 ID、创建日期、任务场景、触达方式、目标用户数、状态、操作 |
| 全部任务／普通消息通知 | Push 下发数／点击 UV、Push 点击率、弹窗下发／曝光／点击、弹窗曝光率／点击率 |
| 回访问卷 | 业务消息数、完成进度、正常／异常数、R1—R5 各等级完成数／总数及完成率进度条 |

无统计分母显示“—”；进度条无数据时宽度为 0。任务表支持横向滚动，更多操作菜单不能被表格裁切。分页原型为每页 7 条。

操作：查看详情、运营效果、终止任务。导出当前筛选任务；普通通知的问卷完成类字段显示“不适用”语义，当前导出为“—”。

### 3.2 任务生命周期

| 状态 | 进入条件 | 允许操作 |
| --- | --- | --- |
| 待执行 | 当前时间早于生效开始时间 | 查看、终止 |
| 执行中 | 已到开始时间且未到结束时间 | 查看、运营效果、满足条件时补发、终止 |
| 已完成 | 到达生效结束时间 | 查询历史与导出，不可补发 |
| 已终止 | 运营确认终止 | 查询历史与导出，不可恢复或补发 |

任务完成不由问卷完成率触发。问卷完成率达到 100% 不自动结束任务；到期完成也不代表业务消息已全部完成。结束时间同时控制发送与作答，到期后禁止新答卷提交；已完成记录仍可回显。终止保留既有消息、快照与审计记录，不撤回已发送的 Push；终止后不允许继续提交问卷。

正式后台须在下发及补发提交时重新校验状态，防止界面状态过期导致越界发送。原型打开时每 30 秒推进状态，关闭页面后无调度。

### 3.3 任务详情

通用：任务名称、状态、ID、创建人、创建时间、生效时间、人群、子业务类型、场景、触达配置、批次记录和运营效果。

- 普通消息通知：展示载体指标；页签为任务概览、批次记录、目标用户、触达配置。不展示业务消息、快照和业务完成率。
- 回访问卷：展示基线消息数、总完成数、正常／异常完成；页签为任务概览、批次记录、业务消息、基线快照、触达配置。概览支持产品风险 R1—R5／客户风险 C1—C5 维度统计。
- 批次记录：批次 ID、类型、创建时间／人、人数、消息数及对应场景指标。普通通知明细跳转推送/弹窗明细，问卷明细跳转业务消息管理并携带任务和批次筛选。

## 4. 新建任务

弹窗标题为“新建任务”。任务提交成功后，固定原始人群；问卷任务同时生成业务消息和基线快照。待执行任务到生效时间才生成首次下发批次。

### 4.1 基础配置

| 字段 | 规则 |
| --- | --- |
| 任务场景 | 必选，单选：普通消息通知、回访问卷；当前默认回访问卷 |
| 任务名称 | 必填，最长 80 字符 |
| 子业务类型 | 必选：我的提醒、交易；独立于任务场景 |
| 问卷版本 | 仅问卷场景展示，新任务必选；原型 V2.1／V2.0；历史未填写任务保持兼容 |
| 生效开始时间 | 必填；未来时间进入待执行，否则进入执行中 |
| 生效结束时间 | 必填，晚于开始时间且不能早于当前时间 |
| 目标人类型 | 问卷展示，默认全部；全部与个人／机构／产品互斥；非全部可多选且至少一项 |
| 人群筛选 | 问卷：全部私募持仓客户、全部私募持仓&高龄客户、导入 UID；通知：全部个人客户、导入 UID |
| UID 导入 | CSV／TXT，按行或逗号分隔；忽略 uid 表头，去空白及去重；最多 500 个 UID，字母、数字、下划线或连字符，最长 64 字符 |
| 备注 | 选填 |

通知任务仅面向个人客户，至少选择 Push 或 App 弹窗一种载体。问卷机构／产品户只创建业务消息，不生成 Push／弹窗；个人客户可以不选载体，以业务消息和线下处理开展回访。

真实人群规则已确认：

- 全部私募持仓客户指快照创建时私募有持仓的客户；该持仓圈选人群后续清仓后排除触达，但保留历史基线和业务消息，不缩减业务统计分母。
- 高龄指快照创建时年龄大于等于 65 岁；高龄圈选同时满足私募持仓条件。
- 导入 UID 直接指定人群，不要求满足持仓条件；但问卷业务消息仍按客户全部符合条件的持仓产品生成，不凭空生成产品记录。
- 创建时固定用户、产品和风险基线，补发不扩充人群。每次实际发送前重新检查用户是否仍允许触达。
- 导入 UID 不存在或不符合其他资格时逐项返回排除原因，不能静默忽略。

原型未接真实持仓、身份、人群服务；人数及产品为模拟数据，不代表已完成真实资格校验。导入无持仓用户的问卷落地行为尚需确认，见第 13 节。

### 4.2 Push 配置

| 字段 | 规则 |
| --- | --- |
| 标题、摘要 | 启用 Push 时必填 |
| android 通道 | 单选：我的提醒、系统通知 |
| 跳转类型 | 单选：原生页面、App 内嵌 H5、普通外部 H5 |
| 原生页面 | 仅原生类型展示，单选页面名称 |
| 跳转地址 | 仅内嵌／外部 H5 展示，必填完整 HTTPS 链接 |

配置标题旁展示“仅对个人客户有效”。不再展示“厂商消息类型”。Push 保留通知样式预览。

### 4.3 App 弹窗配置

必填：弹窗标题、弹窗内容、主按钮文案、跳转类型及其条件字段、展示频次、至少一个展示页面。关闭按钮可勾选，默认展示。配置旁提示“仅对个人客户有效”。不展示原弹窗卡片预览。

展示页面多选：理财首页、私募首页、资产二级页面、自选、公募基金详情、私募基金详情。

| 回访问卷展示频次 | 普通通知对应频次 |
| --- | --- |
| 任务周期内一次 | 任务周期内一次 |
| 未全部完成用户每日一次 | 每日一次 |
| 未全部完成用户每3天一次 | 每3天一次 |
| 未全部完成用户每7天一次 | 每7天一次 |

上述选项已实现配置保存与详情展示。已确认按实际间隔 24／72／168 小时，从有效曝光开始计算，按任务＋UID 跨设备统一频控；补发不重置。“任务周期内一次”表示整个任务仅展示一次。创建载体但未有效曝光不消耗次数。以上只控制弹窗，Push 补发另行管理。真实跨设备曝光和频控需后台接入。

问卷“未全部完成”范围为当前任务内该客户全部产品的业务消息：任意一条未提交即未全部完成；全部结果为正常或异常即全部完成，人工录入也计入。异常是已完成，不继续按未完成催填。最后一份问卷完成后不再展示新弹窗，已打开的对应问卷页显示已完成并禁止重复提交。

### 4.4 跳转规则（Push 与弹窗共用）

- 原生页面：下拉显示资产详情页、订单详情页、风险测评；隐藏跳转地址输入框，不允许手动编辑 path，由页面映射自动生成。
- App 内嵌 H5：输入 HTTPS 链接，App 内 WebView 打开。
- 普通外部 H5：输入 HTTPS 链接，按 App 约定打开外部浏览器。
- 非法或不完整链接阻止保存；切换原生类型后使用映射结果，不使用隐藏字段中的历史 URL。
- 原型路由为演示映射；真实页面注册表及产品／订单等路由参数由 App 团队提供，正式发布前完成联调。

## 5. 批次与补发

首次执行生成 batch1；每次补发生成独立 batch2、batch3……。重试同一批次与人为新建补发必须区分。

### 5.1 回访问卷补发

- 仅生效期内执行中的任务可补发，且启用至少一种载体。
- 在原始任务业务消息中选择未提交的个人客户；同用户多个未提交产品仅各载体下发一条。
- 批次固定本次入选业务消息集合，用于批次业务统计；不复制业务消息，不重写基线和答卷。
- 补发后用户提交同一业务消息，对应任务及关联批次完成指标同步变化。批次完成数因此不能直接相加为任务完成数。

### 5.2 普通通知补发

| 范围 | 定义 |
| --- | --- |
| 原始目标人群 | 任务创建时固定的个人客户集合 |
| 任务内未点击用户 | 该用户在任务全部批次、所有载体中都没有点击事件 |
| 弹窗未曝光用户 | 该用户在任务全部批次中没有弹窗曝光／点击；仅启用弹窗时提供该选项 |

支持填写补发备注及附件，展示预计用户数。筛选结果为空不可提交。当前没有真实失败回执，不提供失败用户补发筛选。

正式下发前还须校验注销、黑名单、用户推送开关及频控；记录计划、过滤、实际下发人数及原因。原型只模拟部分资格字段，不代表已接入这些服务。

## 6. 业务消息管理与问卷

### 6.1 查询及字段

四个独立搜索框：客户名称、UID、任务 ID、产品（产品名称或编码）。支持组合查询；UID、任务 ID、产品编码匹配不区分大小写。附加筛选为目标人类型、业务结果、产品风险等级。

列表字段：消息 ID、任务名称、任务 ID、批次 ID（全部关联批次）、客户／UID、持仓产品／产品编码、目标人类型、风险（客户／产品）、完成状态、业务结果、完成时间、操作人／操作时间、附件、操作。

### 6.2 状态与结果

- 完成状态：未提交、已提交。
- 业务结果：未设置、正常、异常。
- 客户提交答卷或运营首次录入结果均计入已完成。
- 完成时间取首次完成时刻，后续复核不覆盖。
- 操作时间、操作人反映人工结果维护；原始答卷另行保留。
- 原型问卷中任一答案为“否”即判异常；正式问卷题目和“有效答复”判定规则待业务确认，不将演示题目视为正式标准。

### 6.3 单条与批量编辑

单条编辑支持正常／异常结果、回访备注（最长 500 字符）和附件。结果修改写入只读历史：类型、修改前后结果、备注、操作人、时间、附件。

批量编辑支持本页全选、跨页保留选择、清空选择；筛选条件变化或业务数据刷新时清空选择。弹窗显示选中条数及未提交／已提交数量，必须选择目标结果后确认。统一结果、备注及新增附件应用到每条选中记录，每条独立记录流水；已有附件保留、首次完成时间与原始快照不变。

正式后台须在提交时逐条校验记录版本；部分失败应返回成功／失败明细，禁止静默遗漏。

### 6.4 用户端问卷

1. 使用登录身份及 task_id、product_id 查询业务消息，后端验证归属和任务作答时间。任务结束时间同时为作答截止时间；到期、终止或尚未生效时禁止提交，已完成答卷允许回显。
2. 已提交时展示已完成状态，隐藏提交入口，不允许重复提交。
3. 未提交时展示问卷，必答题全部完成后才允许提交，可附带附件。
4. 提交时再次校验任务截止时间及状态，防止打开页面后到期仍可提交；后端校验业务完成状态及答卷唯一性；原子写入答卷快照并更新业务结果、首次完成时间等字段。
5. 提交成功后刷新任务及关联批次指标。
6. 重复提交提示“该产品问卷已提交，不可重复提交”。线下已完成但无答卷的记录也禁止客户再次提交。

仅前端隐藏按钮不能防并发重复提交，必须有后端唯一约束与事务。

## 7. 快照与附件

| 快照 | 内容及规则 |
| --- | --- |
| 基线快照 | 创建时记录问卷版本、客户 UID／姓名／类型、脱敏联系方式及证件、产品名称／编码、客户风险、产品风险、生成时间；只读 |
| 答卷快照 | 客户原始提交答案、提交时间、答卷 ID；不存载体 channel 作为业务归属，不因复核改变 |
| 文件快照 | 模板文件与客户答卷 PDF 分开保存；创建时固定模板版本，客户提交后生成答卷归档；复核不覆盖原始答案或 PDF |

文件快照当前仅为 1 页演示模板，不是客户真实签署／作答归档。线下结果录入不伪造答卷；无答卷时明确展示暂无答卷。

原型附件接受 PDF 或图片，每文件不超过 1 MB，保存于浏览器。本地限制不是正式附件服务容量承诺；正式后台须接文件存储、访问鉴权、完整性校验及保留策略。

## 8. 推送/弹窗明细与业务消息明细

### 8.1 推送/弹窗明细

独立搜索框：载体 ID、UID、任务 ID；支持载体类型筛选、任务／批次范围查询和筛选结果导出。

字段：载体消息 ID、UID、任务／批次 ID、载体类型、下发时间、曝光时间、是否点击、点击时间。Push 曝光显示“不适用”，无事件显示“—”。

原型点击及曝光时间使用示例值，正式系统须来自真实事件时间，不能以发送时间替代。

### 8.2 业务消息明细

位于业务消息管理下方，作为同级只读菜单。复用业务消息的独立查询条件和数据字段，不展示结果修改、批量操作等业务动作。保留明细导出；不再提供“任务汇总”“用户载体消息明细”报表页签。

## 9. 指标口径

### 9.1 业务指标（仅问卷）

| 指标 | 公式／去重规则 |
| --- | --- |
| 基线业务消息数 | 当前任务唯一业务消息数（task_id + uid + product_id） |
| 完成数 | 当前结果为正常或异常的业务消息数 |
| 完成率 | 完成数 / 基线业务消息数 |
| 正常／异常完成数 | 当前结果为对应值的业务消息数，复核后重新归类 |
| 正常／异常完成率 | 对应结果消息数 / 基线业务消息数 |
| 产品风险分级完成率 | 同一原始产品风险等级的完成数 / 该等级基线数 |
| 客户风险分级完成率 | 同一原始客户风险等级的完成数 / 该等级基线数 |
| 批次业务完成率 | 本批次固定入选业务消息中的当前完成数 / 本批次入选业务消息数 |

风险维度取任务创建时快照，不随客户或产品最新等级漂移。业务完成按消息计数，同用户多个产品分别计数；目标用户数按 UID 去重。

### 9.2 载体指标（两种场景共用）

| 指标 | 任务级／批次级计算方式 |
| --- | --- |
| Push 下发条数 | 统计范围内计划发送的唯一 Push 载体实例数 |
| Push 点击条数 | 统计范围内发生过点击的唯一 Push 载体实例数 |
| Push 点击 UV | 统计范围内点击 Push 的唯一 UID 数 |
| Push 点击率 | Push 点击条数 / Push 下发条数 |
| 弹窗下发条数 | 统计范围内计划发送的唯一弹窗载体实例数 |
| 弹窗曝光数 | 发生有效曝光的唯一弹窗载体实例数 |
| 弹窗曝光率 | 弹窗曝光数 / 弹窗下发条数 |
| 弹窗点击数 | 发生主按钮点击的唯一弹窗载体实例数；关闭按钮不计入 |
| 弹窗点击率 | 弹窗点击数 / 弹窗下发条数 |
| 弹窗曝光点击率 | 弹窗点击数 / 弹窗曝光数 |

任务范围为全部批次；批次范围仅当前批次。不同批次载体 ID 不同，载体实例数可汇总；同一 UID 跨批次点击只计一个任务 UV，不能累加批次 UV。

例：用户 A 在两个批次各点击一次，共下发 2 条 Push，则任务点击 UV=1、点击条数=2、点击率=100%，而非 50%。同一载体多次点击只计一条点击；原始事件次数可留存，不能混入当前指标。

零分母显示“—”，百分比保留两位小数。点击弹窗可作为已曝光的证据，避免曝光埋点晚到导致点击数大于曝光数。重复事件按 event_id 去重，聚合再按 carrier_id 去重。

已确认“下发条数”统计计划发送数，按计划载体 ID 去重，与当前原型的已生成载体记录口径一致，不以通道受理、发送成功或送达为准。生成计划后的实际发送过滤、失败不回减计划数，实际事件仅影响曝光和点击分子。频次导致同一载体多次展示时，当前指标仍按实例去重，不将展示次数 PV 混入。

### 9.3 更新与导出

业务结果变更后任务／批次完成指标更新；事件采集后载体指标更新。原型本地即时重算；服务 SLA 本期不考虑。

导出为 XLSX，支持任务汇总、业务消息明细、载体消息明细；与筛选结果及页面口径保持一致，敏感信息脱敏。当前浏览器同步生成文件；大批量异步导出、文件有效期等服务要求本期不考虑。

## 10. 后台数据设计与接口职责

以下为正式实现建议，非已交付接口。

| 表／实体 | 关键字段或约束 |
| --- | --- |
| task | task_id、scene、名称、生命周期、开始／结束时间、子业务类型、人群来源、载体配置、创建人 |
| task_target | task_id + uid 唯一、目标类型、纳入依据、生成时间 |
| batch | batch_id、task_id、类型、范围条件、备注、附件、操作人、时间 |
| batch_target | batch_id + uid 唯一、入选及排除原因 |
| carrier_message | carrier_id、batch_id + uid + channel 唯一、状态、跳转配置、发送时间、通道回执 |
| carrier_event | event_id 唯一、carrier_id、事件类型、事件时间、接收时间 |
| biz_msg | biz_msg_id、task_id + uid + product_id 唯一、snapshot_id、完成状态、结果、首次完成及操作时间、附件 |
| baseline_snapshot | snapshot_id、创建时客户／持仓／风险／问卷版本，只读 |
| task_answer_snapshot | answer_id、biz_msg_id 唯一、答案、提交时间、附件及文件关联 |
| carrier_biz_relation | carrier_id + biz_msg_id 唯一；允许通知载体没有业务关联 |
| batch_biz_relation | batch_id + biz_msg_id 唯一；固定批次业务分母 |
| operation_log | 对象 ID、动作、修改前后、原因、操作者、时间、请求追踪 ID |

接口职责：

- 创建任务：校验场景字段、解析真实人群，生成目标集合及条件业务快照，返回任务 ID 与人群预估。
- 查询任务／详情／批次：按场景返回字段及统一统计结果，避免客户端自行拼不同口径。
- 终止任务：状态并发校验、阻止未下发队列继续发送、记录审计。
- 补发预估及提交：预估展示范围；提交重新校验资格，使用请求幂等键生成批次。
- 查询业务消息／编辑结果／批量编辑：版本控制、事务更新及操作记录。
- 查询与提交问卷：身份归属校验、版本校验、唯一答卷、原子更新业务结果。
- 载体回执／曝光／点击采集：认证、幂等消费、迟到处理、归属校验。
- 文件及导出：模板与答卷独立上传／下载及脱敏；异步任务、权限和有效期不纳入本期。

一致性要求：创建事务配合 outbox；消费重试不重复下发；人工补发生成新批次；服务端调度覆盖页面关闭场景；业务结果变化和事件消费触发统计刷新；定期对账与可重算。

## 11. 异常与一致性要求

- 非法表单、空名单、导入超限明确提示；真实名单接入后逐项反馈不存在及不符合条件的 UID 和原因。
- 网络重试和连点不能重复创建任务或重复提交答卷；同一请求保持幂等。
- 提交问卷时重新校验任务状态与结束时间，即使用户提前打开页面，到期后也不能提交。
- 终止后不可继续发送、补发或提交问卷，保留历史快照和结果。
- 复核不得改变首次完成时间、原始答卷和原始 PDF。
- 权限、容量及服务 SLA 本期不考虑，不增加相关界面或本期验收门槛。

## 13. 已确认决策与剩余联调事项

### 13.1 已确认决策

| 事项 | 确认规则 |
| --- | --- |
| 问卷版本 | 回访问卷必填，普通通知不需要；历史未填版本兼容读取 |
| 展示频控 | 有效曝光起算24／72／168小时，任务＋用户跨设备统一；补发不重置、未曝光不消耗；周期内一次指整个任务 |
| 全部完成 | 当前任务客户所有产品均正常或异常，含人工录入；停止新弹窗，问卷页已完成且不可再次提交 |
| 下发口径 | 计划发送数，载体实例去重，不代表成功或送达 |
| 私募持仓人群 | 快照创建时有私募持仓；后续清仓排除触达 |
| 高龄 | 年龄≥65岁 |
| 导入名单 | 直接指定人群，不要求持仓；不存在及不符合资格须明确反馈原因 |
| 业务消息 | 按全部符合条件的持仓产品生成；固定原始用户、产品、风险；补发不扩充，每次发送前复核资格 |
| PDF | 模板与客户答卷分开保存；创建固定版本，提交后归档；复核不覆盖原始答案/PDF |
| 本期载体 | 仅 Push／弹窗；业务消息仅用于问卷，不新增站内信渠道 |
| 结束时间 | 同时控制发送及作答；到期禁止提交 |
| 权限、容量、服务要求 | 本期不考虑 |

### 13.2 剩余联调／边界事项

- App 正式路由、详情参数、最低版本及降级行为仍需 App 团队提供；当前映射为演示。
- 正式问卷题目、“有效答复”判定和答卷 PDF 样式仍需业务提供；当前示例判定不作为正式业务标准。
- 导入 UID 不受持仓门槛限制，但无符合条件的产品时无法生成用户＋产品业务消息：需明确是否仅保留目标用户并停止该用户问卷载体，或提供非产品型问卷入口。不得默认为无效 UID，也不得虚构持仓。原型当前仍使用模拟产品。
